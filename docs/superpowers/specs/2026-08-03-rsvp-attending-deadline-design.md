# RSVP: отказ, дедлайн редактирования, типы приглашений, телефон из env — дизайн

Дата: 2026-08-03

## Цель

Форма RSVP сейчас — «отправил один раз, назад дороги нет» (`submitted: true` → 409 на повтор),
всегда предполагает, что гость придёт, и всегда даёт добавить спутников. Нужно четыре независимых,
но связанных изменения:

1. Явный ответ «приду / не приду», а не только сбор данных на присутствие.
2. Точка невозврата — глобальная дата/время, до которой (не включительно) можно менять ответ;
   после — редактирование закрыто для всех. Задаётся и хранится в БД, правится из админки.
3. Тип приглашения на уровне гостя: с возможностью привести спутников или фиксированное (без
   спутников) — влияет на форму и на серверную валидацию.
4. Телефон в футере — из `.env`, с заглушкой в константах на случай отсутствия переменной.

## Данные

`server/database/schema.ts`:

```ts
export const guests = sqliteTable('guests', {
  // ...существующие поля...
  attending: integer('attending', { mode: 'boolean' }), // nullable: null = не отвечал
  allowCompanions: integer('allow_companions', { mode: 'boolean' }).notNull().default(true)
})

export const settings = sqliteTable('settings', {
  id: integer('id').primaryKey({ autoIncrement: true }),
  rsvpDeadlineAt: integer('rsvp_deadline_at', { mode: 'timestamp' })
})
```

- `attending` — nullable boolean. `null` — гость ещё не ответил. Отдельно от `submitted`.
- `allowCompanions` — новое поле типа приглашения. Существующие гости мигрируют как `true`
  (текущее поведение — с возможностью добавить спутников — не меняется ни для кого).
- `settings` — одна строка (`id = 1`), создаётся миграцией с `rsvpDeadlineAt = null`. Пока не
  задано — редактирование ответа никогда не закрывается (обратная совместимость на старте).
- `submitted` не меняет смысл: как и раньше, «гость хоть раз отправил форму». Но больше **не**
  блокирует повторную отправку — это делает только дедлайн (см. ниже). Ручной чекбокс «Ответил» в
  админке продолжает работать как есть.

Миграция генерируется через `npm run db:generate` после правки схемы.

## Общий флоу формы (`RsvpForm.vue`)

Состояние экрана определяется `submitted` (уже отвечал?) и прошёл ли `rsvpDeadlineAt`:

| Отвечал | Дедлайн прошёл | Экран |
|---|---|---|
| нет | нет | полная форма |
| да | нет | «спасибо»-экран (текст зависит от `attending`) + кнопка «Изменить ответ» → форма, предзаполненная прежним ответом |
| да | да | тот же «спасибо»-экран, без кнопки редактирования |
| нет | да | «приём ответов завершён» |

«Спасибо»-экран **не** показывает детали сохранённого ответа (без дампа выбранных напитков и
т.п.) — только короткое сообщение, различающееся по `attending`:
- придёт → «Спасибо, будем вас ждать» (как сейчас)
- не придёт → «Жаль, что не сможете быть с нами. Спасибо, что сообщили»

### Внутри самой формы

Первое смысловое поле после шапки — переключатель **«Приду» / «Не приду»** (radio/toggle,
обязательный выбор, без дефолта — гость должен явно выбрать).

- **Приду** → показываются все текущие поля: ФИО, телефон, напитки, блок спутников (только если
  `allowCompanions`), комментарий.
- **Не приду** → ФИО, телефон, комментарий. Блоки напитков и спутников скрыты целиком (не просто
  задизейблены).

Текст lede «Если придёте не один — добавьте спутников, одной анкеты на всех достаточно.» —
показывается только когда `allowCompanions === true`. Для фиксированных приглашений эта фраза
убирается целиком, остальной lede-текст без изменений.

Строка дедлайна `«Ждём ответа до {дата}»` дополняется живым обратным отсчётом (дни/часы/мин/сек),
переиспользует `splitRemaining()` из `app/utils/countdown.ts` и визуальный паттерн `TheCountdown`
(интервал на клиенте через `onMounted`/`onUnmounted`, на сервере — статичный рендер). Показывается,
только если `rsvpDeadlineAt` задан.

Если дедлайн уже прошёл, а форма ещё не отправлялась (случай «нет/да» в таблице) — вместо формы
рендерится нейтральное сообщение «Приём ответов завершён», без полей и кнопок.

## Сервер

### `submitRsvp` (`server/api/rsvp.post.ts`)

- Убрать блок `if (existing.submitted) return 409`.
- Новая проверка в начале (после того как найден `existing`): читать `settings` (одна строка),
  если `rsvpDeadlineAt` задан и `Date.now() >= rsvpDeadlineAt` → `{ ok: false, status: 403,
  message: 'Редактирование ответа закрыто' }`. Действует одинаково и на первую отправку, и на
  повторную.
- После валидации схемой: если `data.attending === false` — принудительно писать `drinks: []` и
  удалять всех `companions` (игнорировать то, что прислал клиент в этих полях, а не просто
  доверять фронту).
- Если `!existing.allowCompanions && data.companions.length > 0` → `400` («Спутники недоступны для
  этого приглашения»). Проверка нужна и на фронте (не рендерить блок), и на сервере (не доверять
  чужому телу запроса).
- `submitted: true` выставляется как и раньше при каждой успешной отправке (идемпотентно).

### `shared/schemas/rsvp.ts`

- `rsvpSchema`: добавить `attending: z.boolean()` (обязательное поле).
- `guestPatchSchema` / `guestCreateSchema`: добавить `attending: z.boolean().nullable().optional()`
  и `allowCompanions: z.boolean().optional()`.

### `GET /api/invite/[code]` (`server/api/invite/[code].get.ts`)

Ответ дополняется:
- `attending`, `allowCompanions` — с гостя.
- `companions` — сейчас вообще не возвращаются; нужны для предзаполнения формы при повторном
  редактировании (аналогично джойну в `listGuests()`).
- `rsvpDeadlineAt` — из таблицы `settings` (эпоха в ms или `null`).

`useState('inviteGuest')` и его тип во всех местах, где он читается (`RsvpForm.vue`,
`index.vue`, `invite.global.ts`), расширяются этими полями.

### Новые эндпоинты для дедлайна (админка)

- `GET /api/admin/settings` — `requireAdminSession`, возвращает `{ rsvpDeadlineAt: number | null }`.
- `PATCH /api/admin/settings` — `requireAdminSession`, body `{ rsvpDeadlineAt: string | null }`
  (ISO-строка из `<input type="datetime-local">` или `null` чтобы снять ограничение), апсертит
  строку `id = 1`.

## Админка (`app/pages/admin/index.vue`, `useAdminGuests.ts`)

- Блок сверху страницы: `datetime-local` инпут + кнопка «Сохранить», привязан к
  `GET/PATCH /api/admin/settings`. Пустое значение = ответы никогда не закрываются.
- В таблице гостей: колонка «Придёт» — при редактировании строки select/radio из трёх состояний
  (не отвечал / придёт / не придёт); в режиме создания — селектор типа приглашения «со спутниками /
  фиксированное» (`allowCompanions`), в строке редактирования — тоже можно поменять тип
  существующему гостю.
- `GuestRecord`, `GuestCreateInput` в `useAdminGuests.ts` — добавить `attending`, `allowCompanions`.
