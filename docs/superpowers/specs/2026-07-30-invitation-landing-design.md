## Структура страницы

Семь секций сверху вниз, всё на одном URL:

1. **Обложка** — имена, дата, время, приглашающая фраза.
2. **Наша история** — фото пары (квадратное 1:1) и текст в три-четыре предложения.
3. **Место проведения** — название площадки, адрес, карта.
4. **Дорогие гости** — просьбы к гостям списком.
5. **Обратный отсчёт** — дни, часы, минуты, секунды.
6. **Форма RSVP**.
7. **Подвал** — телефон для вопросов, прощальная фраза.

Секции из референса, которые сознательно не делаем: **тайминг дня по часам** (расписание ещё не
утверждено, на сайте только «16:00») и **дресс-код** (требований к одежде гостей нет).

## Визуальное направление

Светлая льняная палитра, антиква, ощущение печатного приглашения.

| Токен | Значение | Роль |
|---|---|---|
| `--linen` | `#EFE9DF` | основной фон |
| `--linen-deep` | `#E5DDD0` | чередующиеся полосы секций |
| `--paper` | `#F7F3EC` | карточки, поля ввода |
| `--ink` | `#38322B` | текст, подвал |
| `--ink-soft` | `#6E6255` | вторичный текст |
| `--ink-faint` | `#A2957F` | подписи, заглушки |
| `--wheat` | `#B99A62` | акцент: линии, дедлайн, ссылки |
| `--sage` | `#8B9880` | выбранное состояние, фокус |

**Типографика:** Georgia (с фолбэком на Times New Roman) для заголовков и текста, курсив для имён
и заголовков секций; системный гротеск для подписей, лейблов и кнопок — прописными с разрядкой.
Веб-шрифт не подключаем: приличная кириллическая антиква весит сотни килобайт, а Georgia есть
на всех устройствах.

**Тема — только светлая.** Приглашение живёт в одном визуальном мире; токены одинаковы для
`prefers-color-scheme: dark` и для `data-theme`, чтобы переключатель темы не ломал вёрстку.
Это осознанный выбор, а не пропущенная работа.

**Композиция:** колонка шириной 34rem, секции чередуют фоны `--linen-deep` и `--paper`.
Церемониальные блоки (обложка, место, таймер) выровнены по центру, читаемые (история, просьбы,
форма) — по левому краю.

## Контент

Тексты и данные живут в `app/content/wedding.ts` — один объект: имена, дата, адрес, координаты,
дедлайн, телефон, история, список просьб. Компоненты секций читают оттуда и не содержат текста
внутри разметки. Причина: тексты правятся многократно и не автором вёрстки, а дата используется
одновременно таймером, заголовком и OG-описанием — дублировать её нельзя.

На момент написания спеки боевых текстов нет. Пишем осмысленные заглушки на русском (не lorem),
чтобы вёрстку можно было оценивать, и помечаем их в файле контента комментарием `// TODO: текст
от молодожёнов`. Ждём от заказчика:

- историю пары (3–4 предложения);
- список просьб к гостям (в макете стоят примеры про «горько», цветы и трансфер).

## Анимации

**Салют при заходе.** `app/components/TheConfetti.vue` — canvas на весь экран поверх страницы,
мимо кликов. Шесть снарядов взлетают вразнобой от левого и правого края, на вершине разрываются
веером искр и лент. Цвета берутся из палитры приглашения: на льняном фоне яркая радуга выглядит
чужой. Всё длится около шести секунд, после чего канвас прячется сам и перестаёт занимать слой.
Canvas, а не SVG: несколько сотен частиц в разметке — это сотни узлов, которые браузер честно
пересчитывает каждый кадр.

**Появление обложки.** Строки обложки всплывают на загрузке по очереди, CSS-анимацией
с задержками. Скролла ждать нечего — обложка уже на экране.

**Появление секций при скролле.** Директива `v-reveal` (`app/plugins/reveal.ts`) вешает класс,
когда секция доезжает до экрана; наблюдатель отключается после первого показа, чтобы содержимое
не мигало при прокрутке вверх.

Скрытие применяется только тогда, когда есть чем его снять: без `IntersectionObserver` и при
`prefers-reduced-motion` класс не вешается вовсе. Если наблюдатель не отозвался за 1,5 секунды,
срабатывает страховка и содержимое показывается без анимации — пустая страница хуже страницы
без движения. В фоновой вкладке отсчёт страховки откладывается до переключения на неё: ссылку
из мессенджера открывают именно так, и анимацию гость всё-таки увидит.

**Уважение к настройкам.** При `prefers-reduced-motion: reduce` салют не запускается, анимации
и переходы выключены глобально, содержимое стоит на месте.

## Аналитика

Яндекс.Метрика, счётчик `111173886`, с вебвизором, картой кликов и точным показателем отказов.
Тег грузится клиентским плагином `app/plugins/metrika.client.ts`: на сервере счётчику нечего
считать, а флаг `ssr: true` лишь сообщает Метрике, что страница пришла отрендеренной. Для гостей
с выключенным JavaScript в `<head>` отдаётся `<noscript>`-пиксель.

Идентификатор лежит в `runtimeConfig.public.metrikaId` (перекрывается переменной `METRIKA_ID`),
чтобы будущий раздел статистики в админке брал то же значение, а не дублировал число в коде.

Сайт одностраничный, поэтому отправка хита при смене маршрута не настраивается: единственные
другие маршруты — служебные страницы админки, которые в статистике не нужны.

**Следствие для приватности.** Карта и Метрика ставят сторонние куки каждому, кто открыл
страницу, ещё до любого действия гостя. Это осознанный выбор заказчика; отдельного баннера
согласия и политики обработки данных на сайте нет.

## Форма RSVP

Поля соответствуют существующим `rsvpSchema` и таблицам `guests` / `companions` — **миграция БД
не нужна**:

- **Имя и фамилия** — обязательно.
- **Телефон** — необязательно.
- **Напитки** — чекбоксы, вертикальным списком.
- **Спутники** — до трёх, у каждого имя и свой набор напитков.
- **Комментарий** — свободный текст.
- **Honeypot** `website` — скрытое поле, уже поддержано бэкендом.

Вопроса «придёте или нет» на странице нет: в схеме такого поля нет, а его добавление тянет за
собой миграцию, правки админки и CSV. Отказ гость пишет в комментарий, дубли разруливает админ
вручную — как и задумано базовой спекой.

### Список напитков

`DRINK_OPTIONS` в `shared/constants/drinks.ts` заменяется на восемь позиций, по которым реально
закупаются:

```
red_dry     Красное сухое
red_semi    Красное полусладкое
white_dry   Белое сухое
white_semi  Белое полусладкое
sparkling   Шампанское
brandy      Коньяк
vodka       Водка
none        Не пью
```

Ключи `wine` / `beer` / `spirits` / `non_alcoholic` исчезают. Значения лежат в БД как JSON-массив
строк, поэтому миграция не требуется, но **правки нужны в тестах**, где старые ключи зашиты
в фикстуры: `tests/shared/rsvp-schema.test.ts`, `tests/database/schema.test.ts`,
`tests/server/csv.test.ts`, `tests/server/api/rsvp.test.ts`, `tests/server/api/admin-guests.test.ts`,
`tests/composables/useAdminGuests.test.ts`. Экран правки гостя в `app/pages/admin/index.vue`
перечитывает `DRINK_OPTIONS` и подхватит новый список сам.

### Взаимоисключение «Не пью»

`none` не может стоять в одном наборе с любым алкогольным вариантом:

- гость отмечает `none` → все ранее выбранные варианты снимаются;
- гость отмечает алкоголь при выбранном `none` → `none` снимается.

Правило действует независимо для основного гостя и для каждого спутника — у каждого свой набор.

Реализуется в трёх местах, потому что клиентская логика не защищает базу:

1. **`useRsvpForm.ts`** — переключение чекбокса нормализует набор, гость видит результат сразу.
2. **`rsvpSchema`** — `.refine()` на массиве `drinks` (и в `companionSchema`, и в корневой схеме)
   отклоняет набор, где `none` соседствует с чем-то ещё. Сообщение: «"Не пью" нельзя совместить
   с другими напитками».
3. **`guestPatchSchema`** — та же проверка, иначе админ создаст невозможный набор через правку.

### Валидация

Клиент (мгновенный фидбек) и сервер (обязательная повторная проверка) используют одну zod-схему.

| Поле | Правило | Сообщение |
|---|---|---|
| Имя гостя | не пусто, ≥2 символов, содержит букву | «Без имени мы не поймём, кто ответил» |
| Телефон | если заполнен — 10–15 цифр | «Не хватает цифр — нужен номер целиком» |
| Имя спутника | те же правила, что у гостя | то же |
| Напитки | `none` не сочетается с алкоголем | «"Не пью" нельзя совместить с другими напитками» |

Поведение при отправке с ошибками: поля подсвечиваются, под каждым — причина, над формой сводка
с числом незаполненных полей, фокус переходит в первое проблемное поле. Ошибка гаснет, как только
гость начал править это поле, а не по повторной отправке.

## Тестирование

- **Unit (Vitest):** правило взаимоисключения `none` — на схеме и на композабле; валидация имени
  и телефона; обновлённые фикстуры с новыми ключами напитков.
- **Ручной прогон:** отправка формы с пустым именем, добавление и удаление спутников, раскрытие
  телефона, клик по карте, таймер; проверка на узком экране (375px) и на десктопе.
- Компоненты секций отдельными тестами не покрываем — это статичная разметка поверх файла контента,
  ломаться там нечему.
