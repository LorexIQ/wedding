# Система приглашений — дизайн

Дата: 2026-07-31

Дополняет [2026-07-30-wedding-site-design.md](2026-07-30-wedding-site-design.md) и
[2026-07-30-invitation-landing-design.md](2026-07-30-invitation-landing-design.md). Здесь — только
переход от анонимной RSVP-формы к системе именных приглашений с кодом, гейтом сайта и флагами
статуса. Всё, что не упомянуто, остаётся как в базовых спеках.

## Цель

Сейчас гость создаётся в БД только в момент отправки формы — анонимно, без привязки к конкретному
приглашённому. Нужно перевернуть порядок: администратор заранее создаёт запись гостя (полностью
или частично) и получает пригласительную ссылку с кодом. Гость переходит по ссылке, код
запоминается у него в браузере, и дальше весь сайт — включая форму — работает через эту личность.
Заодно это защита: без ссылки с валидным кодом сайт недоступен.

Из объёма явно вынесено (отдельные спеки):

- Экран-конверт при первом входе и салют при его открытии — зависят от флага `envelopeOpened`,
  который эта спека вводит в схему, но саму анимацию не описывает.
- Защита номера телефона в подвале через API-раскрытие.

## Модель данных

`server/database/schema.ts`, таблица `guests` — три новых столбца:

| Столбец | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `invite_code` | `text`, уникальный индекс | — | Секрет в ссылке `/invite/<code>`. Генерируется сервером при создании, гость его не выбирает. |
| `submitted` | `integer` (bool) | `false` | Гость отправил форму. Раньше об этом судили по самому факту существования строки — теперь строка существует и до ответа. |
| `envelope_opened` | `integer` (bool) | `false` | Гость нажал на конверт при первом входе. Не про сессию — это факт на госте навсегда, пока админ не снимет флаг. |

`companions` не меняется: спутников вносит только гость через форму, своего кода у них нет, связь
— прежний `guest_id`. Миграция — через `drizzle-kit generate`, ручных правок SQL не пишем.

**Генерация кода:** 10 символов, алфавит `A-Za-z0-9` (base62), `crypto.randomBytes`. При коллизии
уникального индекса — до 3 повторных генераций, затем 500 (коллизия при 10 base62-символах и
считанных сотнях гостей практически невозможна, но код должен падать понятно, а не тихо).

## Бэкенд

| Маршрут | Метод | Кто | Делает |
|---|---|---|---|
| `/api/admin/guests` | `POST` | admin | Создаёт гостя-инвайт. Тело — частичный `fio?/phone?/comment?/drinks?`, всё опционально. Генерирует `invite_code`, `submitted=false`, `envelope_opened=false`. Возвращает запись + собранную ссылку. |
| `/api/admin/guests` | `GET` | admin | Как раньше, + `inviteCode`, `submitted`, `envelopeOpened` в каждой записи. |
| `/api/admin/guests/[id]` | `PATCH` | admin | `guestPatchSchema` расширяется полями `fio?` (раньше не редактировалось админом), `submitted?: boolean`, `envelopeOpened?: boolean`. |
| `/api/invite/[code]` | `GET` | публично (по знанию кода) | Резолвит код → `{ fio, phone, comment, drinks, submitted, envelopeOpened }` для гейта и префилла. 404, если кода нет. |
| `/api/invite/[code]/open` | `POST` | публично | Ставит `envelope_opened = true`. Дергается будущим конвертом (саб-проект C); в этой спеке — только сам эндпоинт. |
| `/api/rsvp` | `POST` | публично | Переписывается: см. ниже. |

### Переписанный `/api/rsvp`

Раньше — всегда `INSERT`. Теперь:

1. Код гостя сервер берёт из cookie `invite_code` запроса (`getCookie(event, 'invite_code')`),
   не из тела — гость не должен уметь подставить чужой код в JS.
2. Ищем гостя по `invite_code`. Нет кода в cookie или гостя с таким кодом нет — `404`.
3. `UPDATE` найденной строки данными формы (`fio/phone/comment/drinks`), не `INSERT`.
4. Спутники — старые записи `companions` для этого `guest_id` удаляются, новые вставляются из
   тела запроса. Простая замена, без diff: это даёт корректный результат и при первой отправке,
   и при повторной (админ снял `submitted`, гость подаёт заново).
5. По успеху — `submitted = true`.

Honeypot (`website`) и rate-limit — без изменений.

## Cookie и гейт сайта

Изначально предполагался `localStorage` — заменён на cookie по ходу обсуждения: только cookie
позволяет мидлвари отработать и на SSR, иначе анонимный `curl` без JS видел бы полный HTML до
клиентского редиректа.

- Cookie `invite_code`, `sameSite: lax`, `maxAge` — максимум, который вообще примет браузер.
  Ставим большое число (десятки лет), но нужно понимать: Chromium с 2024 года всё равно обрежет
  реальное хранение примерно 400 днями — это потолок платформы, не наш выбор.
- `app/middleware/invite.global.ts` — глобальная мидлварь. Пропускает `/admin/**`, `/invite/**`,
  `/not-invited` без проверки. На остальных маршрутах: нет cookie, либо `/api/invite/[code]`
  вернул 404 → `navigateTo('/not-invited')`. Если код резолвится — результат кладётся в
  `useState('inviteGuest')`, чтобы страница и форма не делали повторный запрос.
- `app/pages/invite/[code].vue` — точка входа по пригласительной ссылке. Резолвит код через API;
  успех → выставляет cookie, `navigateTo('/')`; код не существует → `navigateTo('/not-invited')`.
- `app/pages/not-invited.vue` — статическая заглушка в стиле сайта: «Вы не приглашены на
  мероприятие, извините :(». Без формы, без гейта на себя.

## Форма RSVP

- Префилл при монтировании — из `useState('inviteGuest')`: `fio/phone/comment/drinks`. Спутники
  не префилятся никогда — их вносит только гость, так решено осознанно.
- Если у гостя `submitted === true` при заходе — форма не рендерится вовсе, вместо неё — тот же
  экран «Спасибо, ждём вас», что сейчас показывается после отправки (значок галочки чуть крупнее).
- Код в запросе `/api/rsvp` явно не передаётся — cookie уходит с запросом сама.

## Админка

Таблица гостей (`app/pages/admin/index.vue`) получает:

- Новую последнюю строку-кнопку «+ Создать приглашение». По клику на её месте появляется
  редактируемая «живая» строка: `fio`, `phone`, `drinks`, `comment` — прямо в ячейках, все поля
  необязательны. Справа — ✓ (создать, `POST /api/admin/guests`) и ✗ (отменить, просто убрать
  черновик). Пока черновик активен — кнопка «Создать приглашение» задизейблена, второй черновик
  открыть нельзя.
- Два чекбокса на каждую обычную строку — «Ответил» (`submitted`) и «Открыл конверт»
  (`envelopeOpened`), сразу патчат `PATCH /api/admin/guests/[id]`. Снятие `submitted` возвращает
  гостю форму при следующем заходе, с префиллом из уже сохранённых данных.
- Кнопка «Скопировать ссылку» на каждой строке — собирает `https://<host>/invite/<inviteCode>` и
  кладёт в буфер обмена.
- Поле `fio` становится редактируемым и в обычном режиме правки (раньше не редактировалось).

## ФИО: форматирование

Новая утилита `app/utils/formatFio.ts` (по аналогии с `phone.ts`): при потере
фокуса поля с ФИ — trim, схлопывание повторных пробелов, каждое слово (в т.ч. после дефиса) с
заглавной буквы. Применяется в трёх местах: поле гостя в `RsvpForm`, поле спутника там же, ячейка
`fio` в живой строке создания инвайта и в редактировании строки в админке.

Жёсткую regex-валидацию формата сознательно не ставим — только мягкая проверка «не пусто, не
длиннее лимита», как сейчас в `rsvpSchema`. Форматирование по blur снимает большинство проблем
(лишние пробелы, случайный капс) без риска отклонить нестандартное, но настоящее имя.

## Тестирование

- **Unit (Vitest):**
  - `submitRsvp` — теперь обновляет существующего гостя по коду, а не создаёт нового; 404 при
    отсутствии/неверном коде; замена списка `companions` на повторной отправке.
  - Генератор кода — уникальность, формат, поведение при коллизии (retry).
  - `/api/invite/[code]` — 200 с ожидаемой формой ответа / 404 на несуществующий код.
  - `formatFio` — набор кейсов: лишние пробелы, дефисные имена, разный регистр на входе.
- **Ручной прогон:** создание инвайта в админке → переход по ссылке → гейт пропускает → форма
  предзаполнена → отправка → повторный заход показывает «спасибо»; заход без cookie/с чужим кодом
  → `/not-invited`; админ снимает `submitted` → форма возвращается с прежними данными.

## Вне рамок

- Экран-конверт и его анимация, салют при открытии (`envelope_opened` эта спека только заводит в
  БД и в эндпоинт `/open` — саб-проект C, отдельная спека).
- Защита номера телефона через API (саб-проект A, отдельная спека).
- Массовое/CSV-создание приглашений — только по одному через живую строку.
- История изменений инвайта, аудит-лог кто и когда снял флаг.

## Открытые вопросы

Нет — все развилки закрыты в обсуждении (cookie вместо localStorage, формат ссылки, объём
предзаполнения, кто создаёт спутников, мягкая валидация ФИО).
