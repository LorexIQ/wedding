# Свадебный сайт-приглашение — дизайн

Дата: 2026-07-30

## Цель

Одностраничный сайт-приглашение на свадьбу с формой регистрации (RSVP) гостей, админ-панелью для просмотра/экспорта/правки заявок, поддержкой OG-превью для соцсетей. Деплой на существующем VPS через Docker, с идентичным локальным запуском на Linux и Windows для тестирования перед выкаткой.

## Архитектура

**Стек:** Nuxt 4 (SSR), TypeScript.

- **Frontend** — одна landing-страница (Vue-компоненты в Nuxt): приглашение, информация о свадьбе, форма RSVP.
- **Backend** — Nitro API-роуты (`server/api/*`) в том же Nuxt-проекте (монолит, без отдельного сервиса).
- **БД** — SQLite-файл, доступ через Drizzle ORM (типобезопасные запросы + миграции).
- **Auth** — сессионная кука (h3 session), один admin-аккаунт, хэш пароля.
- **OG** — `useSeoMeta`/`useHead`, рендерятся на сервере (SSR) — соцсети видят готовый og:title/og:description/og:image при шаринге ссылки.

**Деплой:** один Docker-образ (Nuxt build + Nitro node-server), docker-compose на VPS. SQLite-файл на volume для сохранности между пересборками. Тот же docker-compose локально на Linux и Windows (Docker Desktop) — идентичное окружение для теста перед реальным деплоем.

## Защита от спама/DDoS

- **Cloudflare proxy** перед VPS (domain через Cloudflare, "orange cloud"): гасит объёмный DDoS на сетевом уровне, скрывает реальный IP VPS. Бесплатного tier достаточно.
- **Rate-limit в Nitro**: `/api/rsvp` (POST) — напр. 5 запросов/мин по IP; `/api/admin/login` — напр. 5 попыток/15 мин по IP (защита от брутфорса и спама формы).
- **Honeypot-поле** в форме RSVP — скрытое поле, боты его заполняют, заявка тихо отбрасывается. Дёшево, без капчи.

## Данные и API

**Таблицы (Drizzle schema, SQLite):**

- `guests` — записи RSVP: `id`, `fio`, `phone`, `comment`, `drinks` (JSON-массив), `created_at`, `updated_at`.
- `companions` — доп. гости (+1..+3), привязка `guest_id` (FK): `id`, `guest_id`, `fio`, `drinks` (JSON-массив).
- `admin_users` — один аккаунт: `id`, `login`, `password_hash`.
- Сессии — через подписанную cookie (h3 session), без отдельной таблицы.

**API-роуты:**

- `POST /api/rsvp` — приём формы (валидация, honeypot, rate-limit).
- `POST /api/admin/login`, `POST /api/admin/logout`.
- `GET /api/admin/guests` — список (требует сессию).
- `PATCH /api/admin/guests/:id` — правка записи.
- `DELETE /api/admin/guests/:id` — удаление.
- `GET /api/admin/guests/export` — CSV/Excel-выгрузка.

**Frontend:**

- `pages/index.vue` — landing (приглашение + форма RSVP).
- `pages/admin/login.vue`, `pages/admin/index.vue` — таблица гостей (просмотр, экспорт, правка, удаление), защищено middleware (redirect на login без сессии).

## Форма RSVP — поля

- ФИО (обязательно).
- Телефон.
- Комментарий (свободный текст).
- +1 до +3 сопровождающих — при добавлении каждого появляется своё поле ФИО.
- Напитки — список чекбоксов (несколько вариантов), заполняется отдельно для основного гостя и каждого сопровождающего. Без вопроса про еду.

## Обработка ошибок

- Валидация формы: клиент (zod, мгновенный фидбек) + обязательная повторная валидация на сервере.
- Повторная подача RSVP не блокируется технически — дубликаты разруливает админ вручную (правка/удаление).
- Rate-limit превышен → 429 + понятное сообщение гостю.
- Ошибка БД/сервера → 500 + общий текст гостю, детали в серверный лог.
- Admin-логин: неверные данные → общее сообщение "неверные данные" (не уточнять, что именно неверно). Сессия истекает через 7 дней.
- Экспорт при пустой БД → пустой CSV с заголовками, не ошибка.

## Тестирование

- Unit (Vitest): zod-схемы, CSV-форматирование, honeypot-проверка, rate-limit логика.
- API-тесты: `POST /api/rsvp` (happy path + невалидные данные + rate-limit), admin-эндпоинты (401 без сессии, корректный CSV на экспорте).
- Ручной прогон перед деплоем: локальный Docker Compose на Linux и Windows — форма RSVP глазами, OG-превью (Facebook Sharing Debugger или аналог), админка.
- Без e2e (Playwright) — оверкил для одностраничника.

## Деплой и локальный запуск

- Docker Compose: один сервис (Nuxt/Nitro), volume под SQLite (`./data/wedding.db`), `.env` для секретов (admin login/pass hash, session secret).
- Локально (Linux + Windows): `docker compose up`, тот же образ, что на VPS, порт наружу для теста в браузере.
- На VPS: тот же docker-compose.yml + Cloudflare proxy + Caddy/nginx как reverse-proxy (авто-HTTPS через Caddy проще).
- Бэкапы: SQLite-файл копируется по cron раз в день в отдельное место.
- Деплой вручную: `git pull` + `docker compose up -d --build` на VPS. Без CI/CD-пайплайна.
